<analysis>
Severity legend: CRITICAL (exploitable / RCE-adjacent), HIGH (security or data-loss with realistic trigger), MEDIUM (correctness under normal use), LOW (robustness / drift / minor).

=== CRITICAL ===

C1. No integrity/authenticity verification of downloaded model archives (stt/model-cache.js).
- `_install()` downloads a 65–496 MB archive from `model.downloadUrl`, extracts it, checks only that `expectedFiles` are present and non-empty, writes a manifest, and moves it into userData where sherpa-onnx-node / vosk-koffi load it as native model input.
- There is NO checksum, signature, or even Content-Length/size check. `hashFile()` (sha256) is implemented and exported from model-cache.js but is never called anywhere in the codebase (dead code).
- `model.verified` is a static hardcoded boolean literal in the registry, not the result of any runtime verification, yet the UI surfaces a "verified" status (renderer `model.verified` string), which is misleading to the user.
- Impact: a tampered/replaced GitHub release asset, a compromised mirror, or a network MITM (see C2) can deliver arbitrary payloads that get extracted into the user profile and consumed by native code. This is a supply-chain integrity failure and the highest-risk item in the codebase. It also directly contradicts the AGENTS.md / comment claim that archives are "verified through the real install pipeline."

C2. HTTP protocol downgrade + unrestricted redirect following (stt/model-cache.js downloadFile).
- `const httpModule = url.startsWith('http:') ? require('http') : https;` — plain HTTP is accepted.
- Redirects (3xx) are followed via `new URL(response.headers.location, url)` up to 5 hops with no scheme enforcement, so an `https://` download can be transparently redirected to `http://` and fetched in cleartext.
- No host allow-list. Combined with C1 (no hash), a network attacker can substitute the model archive. Enforce https-only for the initial URL and for every redirect target; reject anything else.

=== HIGH ===

H1. Config can be lost on quit (main.js flushConfigImmediately / will-quit).
- `app.on('will-quit', ...)` calls `flushConfigImmediately()`, which enqueues an async `fs.promises.writeFile` + `rename` onto `writeQueue` but does not (and cannot, from a sync event) await it. Electron proceeds to terminate the process; the async write frequently loses the race.
- Trigger is realistic: user changes the hotkey / pastes an API key / moves the window and immediately quits. The 200 ms debounce plus async flush means the change may never hit disk.
- Fix: perform a synchronous write (`writeFileSync` to temp + `renameSync`) in the flush path.

H2. Autotype "Unicode" mode clobbers the clipboard while the UI promises it doesn't (main.js deliverTranscriptionOutput; index.html output.autotypeNote).
- In `mode === 'autotype'` with `autotypeMethod !== 'paste'`, after a successful `win32.typeUnicodeText(clean)` the code still runs `clipboard.writeText(clean)`. Unicode `SendInput` injection does not use the clipboard, so this write is unnecessary and destroys the user's existing clipboard contents.
- The settings note explicitly says the method "Preserves clipboard." Behavior contradicts the documented/promised contract — a correctness + trust bug and silent data loss (whatever the user had copied is gone).

=== MEDIUM ===

M1. Gemini auth/other errors are misclassified and cause wasteful fan-out (main.js geminiTranscriber).
- Only rate-limit errors are special-cased. An invalid/expired key or a 400/401/403 is not detected, so the loop tries the preferred model + all 4 ladder models (×2 attempts each) for that key, then repeats for every other key, before finally returning a generic `NETWORK_ERROR`.
- A user with a bad key sees "network error" (misleading) and up to ~10 pointless API calls are issued per transcription. Detect 401/403/400 auth errors and fail fast with a distinct code (e.g. AUTH_ERROR / NO_API_KEY).

M2. History read-modify-write has no mutual exclusion (main.js history-delete / history-clear / appendTranscriptionToHistory).
- Each does loadHistory → mutate → saveHistory. Transcriptions are serialized by `SttService.queue`, but history writes are not serialized against the delete/clear IPC handlers. A user clearing or deleting while a transcription is being appended can drop the new item or resurrect deleted items (classic lost update). saveHistory’s temp+rename makes each write atomic but does not prevent the interleave.
- Fix: funnel all history mutations through a single serialized queue (same pattern as SttService.queue), or read-modify-write under an in-process lock.

M3. start-recording-hotkey pending-promise leak / no timeout (main.js).
- Handler sets `isRecordingHotkey = true` and stores `hotkeyPromiseResolve`. If invoked again, or if the user never presses a key / cancels the dialog, the previous promise never settles and `isRecordingHotkey` stays true — the next global keypress is swallowed as "hotkey capture" instead of triggering recording.
- Fix: settle/replace any prior pending resolver, add a timeout that resets `isRecordingHotkey` and rejects, and clear state when the settings window closes.

M4. Oversized/malformed audio is written to disk before validation, and the 60 MB guard is bypassable (main.js transcribe-audio).
- `saveRecordingAudio(request)` runs before any size/shape validation, persisting the payload to `recordings/` first.
- The guard `audioBytes = request.pcm ? request.pcm.byteLength : ...` yields `undefined` when `pcm` arrives as a plain Array (no `byteLength`), so `if (audioBytes && audioBytes > 62914560)` is skipped for that shape. `validatePcm` later bounds it to 15 minutes, so it is not unbounded, but the early guard is ineffective and the file is written regardless.
- Fix: validate size/shape first; only persist after acceptance; compute length via `toFloat32Array().length * 4` rather than `.byteLength`.

=== LOW ===

L1. error-sanitizer over-promises (stt/error-sanitizer.js).
- Patterns catch `AIza…` Google keys and `key=/token=/authorization:` forms only. A secret logged bare (not in a key=value form) or a non-`AIza` key would pass through. The claim that keys "can never reach app.log" is too strong; treat it as best-effort.

L2. Full API keys are stored plaintext as object keys in `keyCooldowns` (main.js).
- `apiKeys` is already plaintext in config.json, but `keyCooldowns` duplicates each key as a JSON property name, widening the plaintext secret footprint. copy-diagnostics happens to redact it (property name matches /key/i), but that coupling is incidental and fragile. Prefer a stable hash/index as the cooldown key.

L3. Dead code and adapter/registry drift.
- No registry model uses backend `vosk`, yet `VoskAdapter` is instantiated and `vosk-koffi` (plus koffi-asar-fix) is loaded — native load cost for an unreachable path. sherpa-adapter carries `parakeet` / `nemo-ctc` / `omnilingual` branches that no live registry entry uses. Remove or gate.

L4. AGENTS.md ↔ model-registry.js divergence.
- AGENTS.md documents tiers as nemo-ctc / mini nemo-transducer / sense-voice / omnilingual(300M, default) / parakeet / fire-red, with specific RAM numbers and "only omni-multilingual remains after validation." The shipped registry uses moonshine / nemo-transducer / sense-voice / whisper-small (the 'light' default) / whisper-large-v3-turbo / fire-red. Users are told they get one model set and download another. Reconcile docs with the registry (whichever is authoritative).

L5. Logger never self-rotates; startup cleanup can delete the live log (logger.js / main.js cleanupJunk).
- `MAX_LOG_BYTES` in logger.js is defined but never enforced during a session, so app.log grows unbounded until the next launch. cleanupJunk deletes `*.log` >5 MB or >7 days at startup, which can remove the current session's app.log mid-run (appendFileSync recreates it, but a concurrent copy-diagnostics tail can miss lines). Add in-session size-based rotation.

L6. bubbleWindow lacks the navigation hardening applied elsewhere (main.js).
- `secureWebContents()` is applied to mainWindow and settingsWindow but not to bubbleWindow. Its content is trusted local markup, but for defense-in-depth apply the same setWindowOpenHandler/will-navigate guard.

L7. NO_SPEECH from the first responding model short-circuits the fallback ladder (main.js geminiTranscriber).
- An empty transcript is treated as terminal (`return NO_SPEECH`) even though a different model in the chain might have produced text. Acceptable as a design choice, but note it: model-specific empties won't trigger fallback.

Non-issues confirmed (not flaws): CSP is strict and script-src 'self'; contextIsolation:true/nodeIntegration:false; IPC listen channels are whitelisted; window open is denied except one exact URL; history and model UI render via textContent (no DOM-based XSS); zip extraction rejects `..`/absolute paths and tar uses strict mode; model-key inputs are regex-validated before path join; download temp/backup dirs are cleaned and installs are made atomic with backup/rollback.
</analysis>

<remediation_plan>
Priority order: C1, C2 → H1, H2 → M1–M4 → L1–L7.

C1 — Verify model integrity before trusting a download.
1. Add `sha256` (and ideally `downloadBytes` as an exact expected size) to every entry in stt/model-registry.js.
2. In model-cache.js `_install()`, after `downloadFile` and before `extractArchive`, call the existing `hashFile(archivePath)` and compare to `model.sha256`; on mismatch, delete the temp dir and throw a distinct `INTEGRITY_FAILED` error.
3. Make `model.verified` mean "has a pinned hash" (compute/derive it), and only show the UI "verified" state when the hash check has actually passed for the installed copy (store the verified hash in installation.json and re-check in getInstalledPath/isInstalled).
4. Add a test in tests/ that asserts every registry entry has a non-empty sha256 and that install rejects a corrupted archive.

C2 — Lock the download transport down.
1. In downloadFile, reject any `url` whose protocol is not `https:` (throw before requesting).
2. On redirect, resolve the target and reject it unless it is also `https:` (and, optionally, matches an allow-list of hosts such as github.com / objects.githubusercontent.com).
3. Keep the 5-redirect cap and 120 s timeout.

H1 — Make the quit flush synchronous.
1. Add a synchronous writer (writeFileSync to `${configPath}.tmp` then renameSync to configPath).
2. In flushConfigImmediately (and the will-quit handler), clear the debounce timer and call the synchronous writer with the current cachedConfig snapshot instead of enqueuing an async write.

H2 — Honor the "preserves clipboard" contract for Unicode autotype.
1. In deliverTranscriptionOutput, remove the `clipboard.writeText(clean)` call on the successful Unicode path (SendInput does not need it). 
2. If a clipboard copy is desired as a convenience, save the prior clipboard text first and restore it after typing, or update the UI note to state the clipboard is overwritten — pick one and make code and copy agree.

M1 — Classify Gemini errors.
1. Add an `isAuthError(err)` helper (status 400/401/403 or /api key|invalid|unauthorized|permission/i).
2. On an auth error, stop the whole loop immediately and return `{ success:false, code:'AUTH_ERROR' }` (or NO_API_KEY) with a user-facing "check your API key" message.
3. Keep rate-limit handling as-is; only genuine transient/network errors should fan out and retry.

M2 — Serialize history mutations.
1. Introduce a module-level `historyQueue = Promise.resolve()` and wrap loadHistory→mutate→saveHistory for append/delete/clear so they run strictly one at a time.
2. Alternatively hold an in-process async mutex around the read-modify-write.

M3 — Fix hotkey capture lifecycle.
1. Before starting a new capture, if `hotkeyPromiseResolve` exists, resolve it with the current hotkey (no-op) or reject it, and reset state.
2. Add a timeout (e.g. 10 s) that sets `isRecordingHotkey=false`, clears the resolver, and resolves with the existing hotkey.
3. Reset capture state on settings-window 'closed'.

M4 — Validate before persisting; fix the size guard.
1. Compute audio length from `toFloat32Array(request.pcm).length * 4` (or arrayBuffer.byteLength) so the 60 MB check can’t be bypassed by an Array payload.
2. Run the size/shape check (and reject) before calling saveRecordingAudio, so invalid/oversized payloads are never written to disk.

L1 — Right-size the sanitizer claim: broaden patterns where feasible (also match bare tokens with a length/entropy heuristic if you keep the promise), and downgrade the "never" wording in comments/AGENTS.md to "best-effort redaction."

L2 — Use a non-secret cooldown key: store cooldowns keyed by a stable hash or by the key’s index in `apiKeys`, not by the raw key string.

L3 — Remove VoskAdapter + vosk-koffi (and koffi-asar-fix if only vosk used it) and the unused sherpa backend branches, or gate them behind actual registry backends. Update stt/index.js accordingly.

L4 — Reconcile AGENTS.md with model-registry.js so documented models, RAM figures, and defaults match what ships; add a test that fails if AGENTS.md model list drifts from the registry keys (optional).

L5 — Enforce logger rotation in-session: in logger._write, if the file exceeds MAX_LOG_BYTES, rotate (truncate or roll to app.log.1) before appending; keep the startup cleanup as a backstop.

L6 — Apply secureWebContents(bubbleWindow.webContents) in ensureBubbleWindow for parity with the other windows.

L7 — If desired, treat an empty transcript as non-terminal: continue to the next model in the chain and only return NO_SPEECH after all models yield empty; otherwise document the current behavior as intentional.

Validation after fixes:
- Add/extend tests under tests/ for: integrity rejection (corrupted archive), https-only enforcement, synchronous config flush on quit, history concurrency, and the audio size-guard bypass.
- Manually verify: quit-immediately-after-settings-change persists; Unicode autotype leaves the clipboard untouched; a deliberately invalid Gemini key returns AUTH_ERROR fast.
</remediation_plan>
