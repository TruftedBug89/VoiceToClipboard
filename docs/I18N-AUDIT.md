# I18N Audit — VoiceToClipboard

Generated by an automated audit of all translation-key usage vs `locales/{en,es,zh}.json`.

Scope: `index.html`, `bubble.html`, `renderer.js`, `bubble-renderer.js`, all `src/renderer/*.js`
(`t()`/`tr()`/`data-i18n*`) and all `src/main/*.js` + `main.js` (`L()`).

## TL;DR

- **No key is missing** from `en.json`, and **parity is clean**: the three locale files have
  identical top-level key sets (219 keys) and an identical nested `appearance` object
  (224 keys after flattening). No empty values, no "untranslated = key" values.
- The flat-dot key bug that this audit follows up on is fully resolved by the new
  `lookup()` (exact flat key first, dotted traversal fallback). All flat keys such as
  `mic.default` / `model.installed` now resolve; only `appearance.style.*`,
  `appearance.widgetStyle`, and `appearance.widgetStyleTooltip` rely on the nested fallback.
- Remaining issues are **not missing keys** — they are dynamic-DOM code paths that use raw
  English strings (or already-translated strings compared against English), plus a few
  dead keys that exist in the locales but are never wired up.

## HIGH severity

### 1. Model card name, description, license, and backend are never localized
`src/renderer/settings-ui.js` · `renderModelCard()` (lines ~288–302)

```js
modelCardName.textContent = model.name;              // raw English
modelCardMeta.textContent = t('model.cardMeta', { backend: backendLabel, ... });
modelCardDesc.textContent = model.description;       // raw English
modelCardLicense.textContent = `License: ${model.license}`; // raw prefix
```

The locale files already contain translated `model.<key>.name` and `model.<key>.desc`
for all 6 registry models, but they are **never used** here. `applyI18n()` does call
`rebuildModelViews()` on language switch, so this is a genuine missed translation, not a
one-time boot issue. The backend labels (`Moonshine`, `Whisper`, `FastConformer
Transducer`, `SenseVoice`, `FireRedASR2`) are also hardcoded English.

### 2. `models.qualityNote` hint is silently destroyed by `applyI18n()`
`index.html` line 164 + `src/renderer/i18n.js` lines ~149–153

`#model-reco-note` contains two pieces of text, but `applyI18n()` replaces the whole
`innerHTML` with only the `models.note` template:

```js
recoNote.innerHTML = t('models.note', { reco, ram });
```

The inner `<span data-i18n="models.qualityNote">…</span>` ("RAM is used only while
transcribing when Power-Saving Mode is on…") is therefore removed after the first
`applyI18n()` run (startup and every language switch), in every language.

### 3. `'✓ MODEL READY'` status is never translated
`src/renderer/settings-ui.js` lines 498 and 850

```js
window.VTC?.recording?.setStatus('done', '✓ MODEL READY');
```

`tr()` (`src/renderer/i18n.js`) only special-cases `'✓ COPIED'` and `'✓ TYPED'`.
Because `'✓ MODEL READY'` carries a leading `✓ `, its normalized form is
`✓_MODEL_READY`, which matches no `status.*` key. Spanish/Chinese users see the raw
English `✓ MODEL READY`.

## MEDIUM severity

### 4. Status badge uses raw-English string comparisons against localized DOM text
`src/renderer/settings-ui.js` lines 831 and 849

```js
statusBadge.textContent.includes('API KEY REQUIRED')
statusBadge.textContent.includes('DOWNLOAD MODEL') || ...includes('MODEL NOT DOWNLOADED') ...
```

After `tr()` localizes the badge ("SE REQUIERE CLAVE API", "DESCARGAR MODELO", …), these
English substring checks fail, so the badge is not cleared when the condition is resolved
in non-English UIs.

### 5. History list is not re-localized on language switch and mixes raw strings
`src/renderer/settings-ui.js` · `renderHistoryList()` (lines 657–744)

- Buttons correctly use `t('history.copy')` / `t('history.paste')` / `t('history.delete')`.
- But the engine badge is raw: `'Gemini' : 'Offline'` instead of `t('engine.gemini')` /
  `t('engine.offline')` (line 683).
- The meta suffix is raw: `` `${item.chars} chars` `` (line 689).
- `applyI18n()` does **not** re-run `renderHistoryList()`, so an already-open history list
  stays in the previous language until another action triggers a re-render.

### 6. Mic device `<select>` is rebuilt without i18n data and not refreshed on language change
`src/renderer/audio.js` · `populateMicDevices()` (lines 135–168)

`populateMicDevices()` calls `micSelect.replaceChildren()` and adds a new default option
via `defaultOpt.textContent = t('mic.default')`. That dynamic option has no `data-i18n`
attribute, so `applyI18n()` cannot re-localize it, and `populateMicDevices()` is only
re-run on `devicechange` — never on UI-language change. Fallback strings
`\`Microphone ${idx + 1}\`` and `\`${micDeviceLabel} (Disconnected)\`` are also raw English.

### 7. Model dropdown's collapsed "current" label is raw English
`src/renderer/settings-ui.js` · `updateDropdownCurrent()` (line ~209)

```js
modelDropdownCurrent.textContent = lbl.name; // MODEL_TIER_LABELS, raw English
```

The dropdown option rows use translated `models.tier.*`, but the collapsed current-selection
label uses `MODEL_TIER_LABELS[tier].name` (English) and is never translated.

## LOW severity

### 8. Remaining raw strings in dynamic DOM
- `src/renderer/settings-ui.js` line 140: `{ es: 'Español', zh: '中文', en: 'English' }` for
  `models.langNote` interpolation (locale `lang.es` / `lang.zh` / `lang.en` exist).
- `src/renderer/audio.js` lines 154/164: `Microphone ${n}` and `(Disconnected)` fallbacks.
- `src/renderer/settings-ui.js` line 302: `License: ` prefix.

### 9. Hardcoded window title and close-button labels
- `index.html` line 7: `<title>VoiceToClipboard</title>` (the `app.name` and
  `settingsWindow.title` locale keys exist but are unused).
- `index.html` line 63: `aria-label="Close Settings"` / `title="Close Settings"` on the
  close button are raw English.

### 10. Translation keys present but never used (locale drift)
These are not user-visible bugs, but indicate dead or unfinished wiring:

- `model.*.desc` ×6 — should be wired into `renderModelCard()` (see HIGH #1).
- `welcome.*` ×7 — no first-run tour markup exists in `index.html` anymore.
- `spacepaste.*` (`label`, `after`, `style`, `style.bubble`, `style.toast`,
  `styleBubble`, `styleToast`) ×7 — replaced by `output.*` UI.
- `settingsWindow.title`, `models.fast`, `mic.testing`, `gemini.onePerLine`,
  `gemini.cooldownNote`, `history.emptyHint`, `bubble.escDismiss`, `bubble.toPaste`,
  `autostop.rec`, `autostop.seconds`, `appearance.idleOpacityVal`, `app.name`.

### 11. `data-i18n-hint` tooltip infrastructure is currently unused
`applyI18n()` handles `[data-i18n-hint]` and `i18n.js` wires `.info-hint` tooltips, but no
markup in `index.html` / `bubble.html` uses those attributes/classes.

## Verification notes (what was checked and found clean)

- **Key enumeration**: 100 `data-i18n*` attribute uses (99 distinct keys), 101 literal
  `t('...')` calls (76 distinct keys), 12 literal `L('...')` calls (11 distinct keys, all
  top-level flat).
- **Missing keys**: 0 used keys are missing from `en.json`. The only non-resolvable
  artifacts in scan output are the dynamic prefixes `model.` and `models.tier.` (string
  concatenation, not keys).
- **Parity**: `es.json` / `zh.json` contain the exact same key set and nested structure as
  `en.json` (no missing keys, no empty/untranslated values).
- **Dynamic key construction**: `model.<key>.name` (6 registry keys) and
  `models.tier.<tier>` (6 tiers) all resolve; each call site supplies an English fallback.
- **`tr()` status mapping**: all 22 `status.*` keys are flat top-level string keys
  (`status.COPIED`, `status.REC`, `status.TRANSCRIBING`, …) matching the `status.<NORM>`
  construction, except the `✓ MODEL READY` case in HIGH #3.
